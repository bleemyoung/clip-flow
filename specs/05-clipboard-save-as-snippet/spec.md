# 05 Clipboard 另存为 Snippet 需求（草案）

状态：需求草案，尚未实施。本文记录目的、交互规则和验收标准。与 04 保持独立，执行顺序必须为“05 另存为 Snippet → 04 手动上云”，本需求可在后端未运行时独立验收。

## 目标与依据

将自动采集的临时剪贴板文本，经用户主动确认，保存为可长期复用的 Snippet。

根 `CONTEXT.md` 定义 Snippet 为“用户主动保存、可长期复用的标题和文本内容”，并明确其不同于自动采集的剪贴板历史。本功能创建独立片段副本，符合这一区分。

`../02-snippets-local/spec.md` 已定义本地 Snippets 新增、校验与持久化能力；本需求复用现有能力，为 Clipboard 增加入口。与 `../04-snippets-upload/spec.md` 的手动上云需求独立，可分别实施和验收。

共同原则：Clipboard 和 Transform 本地运行，只有 Snippets 提供手动上云。启动、复制、另存、新增、编辑和保存均不自动上传。01—03 的历史范围与验收记录保持不变。

## 交互规则

- Clipboard 普通记录与置顶记录的操作区均增加“另存为 Snippet”按钮，沿用现有样式。
- 点击后在当前 Clipboard 页面显示标题、内容与保存、取消操作；正文预填点击时该条历史记录的文本快照，保留换行和排版。
- 标题默认留空，由用户填写；内容可编辑。标题与内容去除首尾空白后均须非空，持久化规则复用现有 Snippets 服务。
- 点击保存，通过现有 `window.clipflow.createSnippet` 能力创建本地 Snippet，不直接读写文件。
- 保存成功后关闭表单，显示“已保存到 Snippets”；用户进入 Snippets 后可以查找、编辑、删除和复制新片段。
- 保存失败保留表单输入，显示明确错误，允许用户手动重试。保存期间禁用重复提交及表单修改，防止连续点击创建多条记录。
- 取消不创建片段。切换模块放弃尚未保存的表单，不隐式保存。

## 数据边界

- 新片段拥有独立 ID、创建时间与更新时间，按现有 Snippets 排序规则显示。
- 原剪贴板记录的 ID、正文、时间和置顶状态均保持不变；不触发复制操作或刷新历史时间。
- 保存后的片段独立持久化到 `snippets.json`，不受普通历史 50 条上限、历史删除或清空操作影响。
- 用户保存的是长期使用的片段；后续升级或接入后端不得沿用 02、03 早期“测试数据可废弃”的规则清空已有数据，须兼容并保留现有片段。
- 两者没有同步关系：删除或编辑任意一方不自动影响另一方。
- 表单采用打开时的文本快照；后续剪贴板轮询或原记录移除不覆盖用户正在编辑的内容。
- 允许用户另一次主动保存相同文本，与现有 Snippets 允许重复的规则一致。
- 新片段初始为“未上云”，不继承其他片段的后端关联或提交状态；状态展示由 04 实施，本需求不以其完成为前提。
- 不调用 Java API，不依赖后端启动，也不自动上云。若后续需要提交后端，用户在 Snippets 中单独点击上云按钮；后续手动更新同一后端记录的规则由 04 定义。

## 验收标准

1. 普通记录和置顶记录都能打开预填正文的表单，多行文本排版保持。
2. 填写标题并保存后，在 Snippets 中出现独立记录；重启应用后记录仍存在。
3. 原记录的内容、时间及置顶状态保持；之后删除、清空或裁剪历史不删除片段，后续升级亦保留原有片段。
4. 标题或正文为空白时不能保存；取消不创建记录。
5. 保存期间连续点击只创建一条记录；保存失败时输入保留，操作恢复。
6. 表单打开期间剪贴板轮询继续，原记录被刷新或移除不改变已预填或编辑的正文。
7. 未启动 Java 服务也能完整使用本功能，且不会产生后端 HTTP 请求。
8. 与 04 联合验收时，新片段为“未上云”，无后端关联；只有另行点击上云才产生请求。05 单独验收不要求 04 界面或 Java 新接口已实现。
9. 使用适当的组件测试验证预填、保存、取消、重复点击与失败恢复，并完成现有测试和构建检查；记录实际验收系统，未经验证的 Windows 或 macOS 项目不标记完成。

- 标签、分类、附件或非文本内容。
